# Interactive Demo

This folder contains the lightweight Streamlit presentation layer for the final project.

The demo **does not recompute the analysis**. It reads the compact CSV/JSON/PNG outputs generated by the reproducible pipeline, which keeps the presentation fast and allows the hosted app to run without the large local Parquet corpus.

---

## Run locally

From the project root:

```bash
python -m pip install -r requirements.txt
streamlit run demo/app.py
```

If the Q1/Q2/Q3 result outputs are missing, generate them first:

```bash
python code/run_project.py
streamlit run demo/app.py
```

---

## Demo data requirements

The app reads compact result artifacts from:

```text
data/analysis/q1/tables/
data/analysis/q1/figures/report/

data/analysis/q2/tables/

data/analysis/q3/tables/
data/analysis/q3/figures/report/
```

It does **not** need these large/reproducible intermediates at runtime:

```text
data/analysis/timelines/
data/analysis/q1/predictions/
data/processed/tracking/linked/
data/processed/tracking/coverage_audit/
data/processed/analysis_audit/
```

It also does not need the canonical `data/processed/full_*` Parquet corpus when the compact analysis outputs already exist.

## What the demo shows

### Overview

- dataset scale;
- the three research questions;
- a concise takeaway from each problem.

### Problem 1 — Temporal Behavior

- primary Q1 sample size;
- held-out AUC results;
- adjusted within-player behavioral effects;
- region/hypothesis controls;
- report prediction figure;
- methodological interpretation notes.

### Problem 2 — Champion Pairings

Select a champion and inspect:

- appearances / pick rate / win rate;
- most common partner;
- strongest normalized partner;
- high-support descriptive win surplus;
- interactive `log2(lift)` vs win-surplus scatter;
- sortable partner table.

### Problem 3 — Champion Network

Select a champion and inspect:

- Louvain community;
- association-weighted PageRank;
- weighted network degree;
- strongest supported association neighbors;
- community role composition;
- strong cliques containing the champion;
- full report network figure.

---

## Recommended 2–3 minute presentation path

1. Open **Overview** and state the three complementary questions.
2. In **Problem 1**, show that the adjusted effects are small/inconsistent and that behavior adds only a small held-out AUC gain.
3. In **Problem 2**, select a recognizable champion and compare its most common partner with its strongest normalized partner.
4. Move to **Problem 3** and select the same champion to show how a pair-level relationship becomes part of a larger network/community structure.
5. Close with the final message: temporal behavior is weak, pair association differs from popularity/performance, and graph structure reveals richer team-composition patterns.

## Deploy to Streamlit Community Cloud

The demo is designed to be deployable directly from GitHub.

Before deployment, make sure the repository contains:

```text
demo/app.py
.streamlit/config.toml
requirements.txt

data/analysis/q1/tables/
data/analysis/q1/figures/report/

data/analysis/q2/tables/

data/analysis/q3/tables/
data/analysis/q3/figures/report/
```

Then:

1. connect the GitHub repository to Streamlit Community Cloud;
2. choose the repository and branch;
3. set the app entry point to:

```text
demo/app.py
```

4. deploy.

The hosted app reads only the compact committed analysis artifacts, so the large local `data/processed/full_*` inputs do not need to be uploaded to Streamlit.

A custom domain is not required.

> Hosting behavior such as idle sleeping is controlled by Streamlit Community Cloud and may change over time. The project itself does not depend on a specific hosting policy.

## Interpretation

The dashboard intentionally mirrors the scientific limitations in the report:

- no target-match leakage in Problem 1;
- no causal claim about psychological tilt or fatigue;
- no causal claim that pair win surplus is champion synergy;
- graph communities describe observed co-selection structure and may reflect role complementarity, patch/meta, and selection effects.

The demo is a **presentation layer over the validated analysis**, not a separate modeling workflow.
